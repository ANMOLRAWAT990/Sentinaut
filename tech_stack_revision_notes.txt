PART 1: EXECUTIVE SUMMARY & SYSTEM ARCHITECTURE
====================================================================================================

The SentiNaut platform is a modern, full-stack, AI-driven web application designed to analyze 
text and determine its sentiment (positive, negative, neutral) using advanced Large Language 
Models (LLMs). 

The architecture follows a decoupled Client-Server model.
- The Client (Frontend) is a Single Page Application (SPA) built with React.
- The Server (Backend) is a high-performance RESTful API built with Python and FastAPI.
- The Database is MongoDB, chosen for its flexible, document-oriented schema which perfectly fits 
  JSON payloads.
- The AI Engine is powered by Google's Generative AI (Gemini).

Why Decoupled?
Decoupling the frontend from the backend allows both systems to scale independently. The backend 
acts purely as a data provider (JSON APIs), which means in the future, if you wanted to build a 
mobile app (iOS/Android), the same backend could be reused without a single line of code changed.

Workflow Contribution Overview:
- Frontend handles 100% of the User Interaction.
- Backend handles 100% of Data Validation, Security, and API routing.
- Database handles 100% of state persistence (saving data permanently).

PART 2: FRONTEND DEEP DIVE & COMPONENT BREAKDOWN
====================================================================================================

The frontend is the face of SentiNaut. It must be fast, responsive, secure, and visually stunning.

-------------------------------------------------------------------------
2.1 CORE FRAMEWORK: REACT (v19)
-------------------------------------------------------------------------
* DEFINITION: A declarative, efficient, and flexible JavaScript library for building user interfaces 
  based on reusable UI components. It utilizes a Virtual DOM to optimize rendering.

* WHY DID I USE IT?
  React is the industry standard for Single Page Applications (SPAs). Unlike traditional HTML/JS where 
  the whole page reloads, React only updates the specific parts of the screen that change, making 
  the app feel like a seamless desktop application.

* ADVANTAGES:
  - Component-based architecture allows for massive code reusability.
  - Huge ecosystem and community support.
  - Virtual DOM ensures high performance during complex UI updates.

* DISADVANTAGES:
  - Steep learning curve (JSX, Hooks, state management).
  - Requires a build step (Vite/Webpack).
  - Can suffer from performance issues if unnecessary re-renders are not managed properly.

* WORKFLOW CONTRIBUTION (100% of UI Rendering):
  React is responsible for rendering the entire visual interface. From the moment the user opens 
  SentiNaut, React is drawing the screen, managing local state (like what text the user is typing), 
  and deciding when to send that data to the backend.

HOW IT WORKS IN SENTINAUT (Code Example):
The application is broken down into reusable components (Layout, Page, UI Components).
```jsx
// src/components/ui/Button.jsx
import React from 'react';

const Button = ({ onClick, children, variant = "primary" }) => {
    // Tailwind classes applied dynamically based on variant
    return (
        <button onClick={onClick} className={`btn ${variant}`}>
            {children}
        </button>
    );
};
export default Button;
```

-------------------------------------------------------------------------
2.2 BUILD TOOL: VITE
-------------------------------------------------------------------------
* DEFINITION: A next-generation frontend build tool that significantly improves the frontend 
  development experience by using native ES modules.

* WHY DID I USE IT?
  Older tools like Create React App (Webpack) are extremely slow to start. Vite starts the 
  development server in milliseconds and updates the browser instantly when I save a file.

* ADVANTAGES:
  - Near-instant server start time.
  - Lightning-fast Hot Module Replacement (HMR).
  - Optimized production builds using Rollup.

* DISADVANTAGES:
  - Newer than Webpack, so some very old plugins might not be supported.

* WORKFLOW CONTRIBUTION (100% of Development & Build Workflow):
  Vite doesn't run in production. It is 100% responsible for the developer experience and compiling the raw React code into minified JavaScript/CSS.

-------------------------------------------------------------------------
2.3 ROUTING: REACT ROUTER DOM
-------------------------------------------------------------------------
* DEFINITION: A library that enables dynamic routing in a web app without refreshing the page.

* WHY DID I USE IT?
  In an SPA, we don't want the browser to reload the page when a user clicks a link. React Router 
  intercepts the URL changes and seamlessly swaps out the components on the screen.

* ADVANTAGES:
  - Smooth page transitions without server reloads.
  - Supports nesting and dynamic route parameters.

* DISADVANTAGES:
  - Complex to set up authentication guards.

* WORKFLOW CONTRIBUTION (100% of Navigation):
  Controls what component is rendered based on the URL.

HOW IT WORKS IN SENTINAUT:
We use a `<BrowserRouter>` that wraps our app. SentiNaut uses "Protected Routes", checking if a user has a valid JWT token in their LocalStorage before allowing access to the dashboard.
```jsx
<Routes>
    <Route path="/" element={<Home />} />
    <Route path="/login" element={<Login />} />
    {/* Protected Route */}
    <Route path="/dashboard" element={
        isAuthenticated ? <Dashboard /> : <Navigate to="/login" />
    } />
</Routes>
```

2.4 STYLING: TAILWIND CSS (v4)
-------------------------------------------------------------------------
* DEFINITION: A utility-first CSS framework packed with classes like `flex`, `pt-4`, `text-center` that can be composed to build any design.

* WHY DID I USE IT?

* ADVANTAGES:

  - Automatically purges unused CSS, leading to tiny file sizes.

* DISADVANTAGES:

* WORKFLOW CONTRIBUTION (100% of Styling):
  Every single color, margin, padding, and responsive layout (mobile vs desktop) is handled by Tailwind.

2.5 ANIMATIONS & VISUALS: FRAMER MOTION & LUCIDE REACT
-------------------------------------------------------------------------
* DEFINITION: Framer Motion is a production-ready motion library for React. Lucide React provides modern SVG icons.

* WHY DID I USE IT?
  A static application feels cheap. Framer Motion adds "wow factor" through physics-based animations.

* ADVANTAGES:

* DISADVANTAGES:

HOW IT WORKS IN SENTINAUT:

```jsx

    animate={{ opacity: 1, y: 0 }} 
    transition={{ duration: 0.5 }}

    <h1>Welcome to SentiNaut</h1>

```

PART 3: BACKEND DEEP DIVE & LOGIC BREAKDOWN
====================================================================================================

The backend is the brain of the operation. It must be secure, fast, and resilient.

-------------------------------------------------------------------------
3.1 CORE FRAMEWORK: FASTAPI & UVICORN
-------------------------------------------------------------------------
* DEFINITION:
  - FastAPI: A modern, fast (high-performance) web framework for building APIs with Python 3.8+.
  - Uvicorn: An ASGI (Asynchronous Server Gateway Interface) web server.

* WHY DID I USE IT?
  FastAPI is arguably the fastest Python web framework available. It supports asynchronous programming (`async/await`), which is crucial when waiting for slow external services (like calling the Gemini AI API).

* ADVANTAGES:
  - Insanely fast (on par with NodeJS/Go).
  - Automatic interactive API documentation (Swagger UI).
  - Built-in data validation via Pydantic.

* DISADVANTAGES:
  - Younger ecosystem compared to Django.
  - `async/await` paradigms can be confusing for beginners.

* WORKFLOW CONTRIBUTION (100% of API Layer):
  Every single request from the React frontend goes through FastAPI.

HOW IT WORKS IN SENTINAUT:
We define endpoints using decorators.
```python
@app.post("/api/analyze")
async def analyze_text(request: AnalysisRequest):
    # Asynchronously wait for Gemini API
    result = await ai_service.analyze(request.text)
    return result
```

-------------------------------------------------------------------------
3.2 DATA VALIDATION: PYDANTIC (v2)
-------------------------------------------------------------------------
* DEFINITION: A data validation and settings management library using Python type annotations.

* WHY DID I USE IT?
  Never trust user input. Pydantic ensures that if an API expects an integer, it gets an integer.

* ADVANTAGES:
  - Catches bad data instantly.
  - Automatically generates 422 Unprocessable Entity error messages.

* DISADVANTAGES:
  - Strictness can sometimes be annoying.

* WORKFLOW CONTRIBUTION (100% of Data Validation Workflow):
  Before FastAPI executes a route function, Pydantic checks the JSON payload.

HOW IT WORKS IN SENTINAUT:
```python
from pydantic import BaseModel, EmailStr

class UserSignup(BaseModel):
    username: str
    email: EmailStr  # Automatically validates email format
    password: str
```

-------------------------------------------------------------------------
3.3 SECURITY: PASSLIB, BCRYPT, PYJWT
-------------------------------------------------------------------------
* DEFINITION:
  - Passlib/Bcrypt: Tools for securely hashing passwords.
  - PyJWT: A tool for encoding and decoding JSON Web Tokens.

* WHY DID I USE THEM?
  Plaintext passwords in a database are a critical vulnerability. Bcrypt hashes them with a salt. JWTs are used because they are stateless; the server doesn't need to look up a session in the database for every request.

* ADVANTAGES:
  - Industry-standard security.
  - Stateless JWTs allow easy backend scaling.

* DISADVANTAGES:
  - JWTs cannot easily be invalidated (logged out) before they expire.

* WORKFLOW CONTRIBUTION (100% of Authentication Workflow):
  - Passlib handles 100% of the User Registration (hashing).
  - PyJWT handles 100% of Route Protection.

HOW IT WORKS IN SENTINAUT:
1. Registration: `Passlib` hashes password with `Bcrypt`.
2. Login: `Passlib` compares hash. `PyJWT` creates a token.
3. Subsequent Requests: Frontend sends JWT in `Authorization: Bearer <token>` header. FastAPI verifies signature.

-------------------------------------------------------------------------
3.4 ROUTING ARCHITECTURE (APIRouter)
-------------------------------------------------------------------------
* WHY DID I USE IT?
  Putting all APIs in one `main.py` file creates an unmaintainable mess.
  FastAPI's `APIRouter` allows dividing routes into logic groups:
  - `routes/auth.py`: Handles `/login`, `/register`, `/google-login`
  - `routes/analysis.py`: Handles `/analyze`, `/history`

-------------------------------------------------------------------------
3.5 RESILIENCE: TENACITY
-------------------------------------------------------------------------
* DEFINITION: A general-purpose retrying library.

* WHY DID I USE IT?
  Network requests fail. The Gemini API might return a 503 error. Instead of crashing, the backend should try again automatically.

* ADVANTAGES:
  - Highly configurable exponential backoff.
  - Improves User Experience (UX).

* WORKFLOW CONTRIBUTION (Resilience Workflow):
  Wraps the Gemini API call. If the AI call fails, Tenacity executes the retry logic.

HOW IT WORKS IN SENTINAUT:
```python
from tenacity import retry, stop_after_attempt, wait_exponential

@retry(stop=stop_after_attempt(3), wait=wait_exponential(multiplier=1, min=2, max=10))
async def call_gemini_api(text: str):
    # Try calling the API. If it fails, wait 2 seconds, then 4, then 8.
    pass
```

PART 4: DATABASE ARCHITECTURE (MONGODB)
====================================================================================================

-------------------------------------------------------------------------
4.1 CORE DATABASE: MONGODB & PYMONGO
-------------------------------------------------------------------------
* DEFINITION:
  - MongoDB: A NoSQL database that stores data in flexible, JSON-like documents (BSON).
  - PyMongo: The official Python driver for MongoDB.

* WHY DID I USE IT?
  Sentiment analysis results can have varying structures. SQL databases require rigid schemas. MongoDB stores BSON, which perfectly aligns with our JSON-based API and the dynamic nature of AI responses.

* ADVANTAGES:
  - Fast for reading/writing simple documents.
  - Flexible schema.

* DISADVANTAGES:
  - Lack of strict joins. Relational queries are difficult.

* WORKFLOW CONTRIBUTION (100% of Data Persistence):
  Every user account and piece of analysis history lives here.

HOW IT WORKS IN SENTINAUT:
Collections (similar to SQL Tables) are used:

1. Users Collection:
   - `_id`: ObjectId
   - `username`: String
   - `email`: String (Unique index)
   - `hashed_password`: String
   - `created_at`: Datetime

2. Analyses Collection:
   - `_id`: ObjectId
   - `user_id`: ObjectId (References Users collection)
   - `input_text`: String
   - `sentiment_label`: String
   - `confidence_score`: Float
   - `timestamp`: Datetime

PART 5: ARTIFICIAL INTELLIGENCE INTEGRATION (GOOGLE GEMINI)
====================================================================================================

-------------------------------------------------------------------------
5.1 CORE ENGINE: GOOGLE GENERATIVE AI
-------------------------------------------------------------------------
* DEFINITION: Google's flagship Large Language Model (LLM), accessed via Python SDK.

* WHY DID I USE IT?
  Traditional sentiment analysis uses basic dictionaries (e.g., checking if the word "bad" is in the sentence). This fails with sarcasm. Gemini actually understands context, sarcasm, and nuance.

* ADVANTAGES:
  - State-of-the-art accuracy in sentiment detection.
  - Can return strictly formatted JSON via prompt engineering.

* DISADVANTAGES:
  - Latency: Takes 1-3 seconds per request.
  - Dependent on external provider limits and costs.

* WORKFLOW CONTRIBUTION (Core Business Logic):
  Responsible for 100% of the actual text analysis generation.

HOW IT WORKS IN SENTINAUT:
1. API Initialization: Loaded using `.env` key.
2. Prompt Engineering: We wrap user text in a "System Prompt" to enforce structured output.
   
   Example Prompt:
   "You are an expert sentiment analysis AI. Analyze the following text and return ONLY a JSON 
   object with two keys: 'sentiment' (must be 'Positive', 'Negative', or 'Neutral') and 'score' 
   (a number from 0 to 100 representing confidence). Text to analyze: '{user_input}'"

3. Parsing Output: The backend receives the JSON string, parses it, and maps it to a Pydantic model.

PART 6: COMPREHENSIVE WORKFLOW TRACING (END-TO-END)
====================================================================================================

To truly understand the stack, let's trace workflows from end to end.

-------------------------------------------------------------------------
WORKFLOW 1: SUBMITTING TEXT FOR AI SENTIMENT ANALYSIS (Complete Breakdown)
-------------------------------------------------------------------------
1. [React & Tailwind] A logged-in user types text and clicks "Analyze".
2. [React] React retrieves the user's JWT from LocalStorage.
3. [React Router & Fetch] HTTP POST is sent to `/api/analyze`.
4. [SlowAPI] Checks the user's IP/ID to ensure they haven't exceeded the rate limit (e.g., 5 requests/min).
5. [FastAPI & PyJWT] Decodes token. If expired, returns 401 Unauthorized. Extracts `user_id`.
6. [Pydantic] Validates the incoming text (not empty, under char limits).
7. [Tenacity] Prepares retry logic for the AI call.
8. [Gemini SDK] Constructs prompt and calls `generate_content()`.
9. [MongoDB & PyMongo] Response is parsed. A new document is created in `analyses` collection.
10. [FastAPI] Returns JSON result to frontend.
11. [Framer Motion & Recharts] Animates the beautiful card onto screen and updates dashboard graphs.

-------------------------------------------------------------------------
WORKFLOW 2: USER REGISTRATION (Traditional Email/Password)
-------------------------------------------------------------------------
1. [Frontend] User fills out signup form.
2. [Backend] FastAPI endpoint receives request.
3. [Backend] Pydantic validates payload (checks '@' symbol).
4. [Backend] PyMongo checks if email exists: `db.users.find_one({"email": payload.email})`.
5. [Backend] Passlib hashes the plaintext password.
6. [Backend] New user inserted into MongoDB.
7. [Frontend] React detects 201 success and redirects to `/login`.

-------------------------------------------------------------------------
WORKFLOW 3: GOOGLE OAUTH LOGIN
-------------------------------------------------------------------------
1. [Frontend] User clicks "@react-oauth/google" button.
2. [Browser] Google popup appears, returns encrypted ID Token to React.
3. [Backend] FastAPI receives token and verifies signature with Google's public keys.
4. [Backend] Checks MongoDB. If no user exists, creates one.
5. [Backend] PyJWT generates a custom SentiNaut JWT valid for our app.
6. [Frontend] React saves JWT in LocalStorage, updating global auth state.

PART 7: DEVOPS, ENVIRONMENT MANAGEMENT & RESILIENCE
====================================================================================================

-------------------------------------------------------------------------
7.1 ENVIRONMENT VARIABLES (PYTHON-DOTENV)
-------------------------------------------------------------------------
* DEFINITION: A library that reads key-value pairs from a `.env` file.

* WHY DID I USE IT?
  Hardcoding secrets (like `MONGODB_URI` or `GEMINI_API_KEY`) into the source code is a catastrophic security risk. The `.env` file is hidden and injected at runtime.

-------------------------------------------------------------------------
7.2 REQUIREMENTS.TXT & PACKAGE.JSON
-------------------------------------------------------------------------
These files lock in exact versions of libraries (e.g., `fastapi==0.138.0`). Ensures that if you deploy to a server, it installs the exact versions tested, preventing unexpected bugs from library updates.

PART 8: SECURITY & RATE LIMITING
====================================================================================================

-------------------------------------------------------------------------
8.1 SLOWAPI (RATE LIMITING)
-------------------------------------------------------------------------
* DEFINITION: A rate-limiting library for FastAPI.

* WHY DID I USE IT?
  Without rate limits, a malicious user could write a script to ping the `/analyze` endpoint 10,000 times a second, crashing the server and racking up massive Gemini API bills.

* WORKFLOW CONTRIBUTION:
  Intercepts 100% of incoming requests to sensitive routes. SlowAPI tracks the IP in memory and returns a 429 Too Many Requests error if exceeded.

-------------------------------------------------------------------------
8.2 CORS (CROSS-ORIGIN RESOURCE SHARING)
-------------------------------------------------------------------------
* WHY DID I USE IT?
  Browsers prevent a frontend on `app.sentinaut.com` from making requests to `api.sentinaut.com` unless allowed. FastAPI's `CORSMiddleware` is configured to allow requests ONLY from specific frontend URLs, preventing unauthorized websites from making calls.

PART 9: PERFORMANCE OPTIMIZATIONS
====================================================================================================

1. Asynchronous I/O: FastAPI utilizes `async def`. While waiting for MongoDB or Gemini to respond, the Uvicorn server can process other users' requests simultaneously without blocking the main thread.
2. Vite Hot Module Replacement (HMR): Only updates the exact component edited, rather than reloading the whole page, saving hundreds of hours of dev time.
3. Tailwind Tree-Shaking: Scans React code and compiles a minified CSS file containing ONLY used classes.
4. Database Indexing: The MongoDB `users` collection has a unique index on the `email` field. This makes checking for duplicate emails during registration O(1) or O(log N) instead of O(N) full scans.
